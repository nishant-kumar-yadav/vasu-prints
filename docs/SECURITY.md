# VasuPrint — Security & Privacy

Scope: the Next.js app, the Hostinger VPS, MongoDB Atlas, SMTP, Cloudinary, Turnstile. Threat model is a small B2B site: the realistic risks are spam/bot floods, malicious uploads, admin account takeover, data exposure of leads/artwork, and server compromise via an unpatched VPS.

---

## 1. Assets and threats

| Asset | Threat | Primary controls |
|---|---|---|
| Lead data (names, phones, emails, specs) | Unauthorised access, leakage via logs/exports | Admin-only access, no PII in logs, Atlas IP allowlist, CSV injection guard |
| Artwork files (customer IP) | Public exposure, enumeration | Stored outside web root, random UUID names, authenticated download only |
| Admin account | Brute force, session theft, CSRF | argon2id, rate limits, httpOnly/secure cookie, Server Action origin checks |
| Server | Malicious upload, RCE via dependency, SSH brute force | Content sniffing, no processing of uploads, dependency audit, SSH key-only, ufw, fail2ban, unattended upgrades |
| Availability | Upload/quote floods, disk fill | Rate limits, Turnstile, Nginx body limits, disk monitoring |
| Brand trust | Spam leads, defacement | Turnstile + honeypot; admin-only content changes |

## 2. Secrets and configuration

- All secrets live in `/srv/vasuprint/shared/.env` (mode `600`, owner `deploy`) on the VPS and in GitHub Actions secrets for deploy only. Never committed. `.env*` in `.gitignore`; `.env.example` lists names with empty values.
- `src/config/env.ts` validates with zod at boot; **no fallback values for secrets** — missing `SESSION_SECRET`, `ADMIN_PASSWORD_HASH`, `SMTP_PASS`, etc. crash startup.
- `server-only` package imported in every module that reads secrets so they can never be bundled to the client. Only `NEXT_PUBLIC_TURNSTILE_SITE_KEY` and `NEXT_PUBLIC_GA_ID` are public.
- Generate: `SESSION_SECRET` → `openssl rand -base64 48`; `IP_HASH_SALT` → `openssl rand -hex 32`; admin hash → `pnpm admin:hash` (prompts for password, prints argon2id hash; params m=19456 KiB, t=2, p=1).

## 3. Admin authentication (single admin)

| Control | Specification |
|---|---|
| Credentials | `ADMIN_EMAIL` + `ADMIN_PASSWORD_HASH` (argon2id) in env. Password ≥ 14 chars, generated by a password manager. |
| Login rate limit | 5 attempts / 15 min / IP; 20 failed attempts / 24 h globally → login locked for 1 h (logged at `warn`). |
| Timing | Always run `argon2.verify` (against a dummy hash when the email mismatches) to avoid user enumeration by timing. |
| Session | `vp_session` cookie containing a JWT (HS256 via `jose`) `{ sub: 'admin', iat, exp, ver }`; `HttpOnly; Secure; SameSite=Strict; Path=/`; lifetime 12 h, sliding refresh when < 2 h remain. |
| Revocation | `SESSION_VERSION` env; incrementing it invalidates all sessions (`ver` claim mismatch). |
| CSRF | Server Actions: Next.js built-in Origin/Host check (keep `serverActions.allowedOrigins` = `[vasuprint.com]`). Route handlers: explicit `Origin` check + `SameSite=Strict`. |
| Authorisation | `requireAdmin()` in the `(panel)` layout **and** at the top of every admin Server Action and admin Route Handler. Test: each action rejects without a session. |
| Password reset | Manual: generate new hash with `pnpm admin:hash`, update `.env`, bump `SESSION_VERSION`, `pm2 reload vasuprint`. |
| Login page | `noindex`, no "forgot password" link, generic error message. |

## 4. Input validation

- Every external input (route handler bodies, query params, Server Action args, `searchParams` used in pages) is parsed with zod. Parsed output is mapped field-by-field to the database; raw objects are never spread into Mongoose (prevents mass assignment and operator injection).
- Mongoose `strict: 'throw'`, `sanitizeFilter: true` set globally (`mongoose.set('sanitizeFilter', true)`).
- Text output is rendered via React (auto-escaped). `dangerouslySetInnerHTML` is allowed only for JSON-LD (built from typed objects with `JSON.stringify` + `<` escaped as `<`).
- Markdown (policies) is rendered with `react-markdown` without `rehype-raw` (no raw HTML).
- Admin-entered rich text: plain text / limited markdown only, same renderer.

## 5. Upload security

| Control | Value |
|---|---|
| Max files per lead | 3 |
| Max size | 100 MB each — enforced by Nginx (`101m` on `/api/uploads`), busboy `fileSize` limit, and byte counter |
| Allowed | cdr, ai, eps, pdf, psd, svg, png, jpg, jpeg, tif, tiff, zip |
| Type validation | Extension allowlist **and** content signature match (`SCHEMA.md` §6). Double extensions (`file.pdf.exe`) → last extension used → rejected. |
| Storage | `UPLOAD_DIR` outside release dir and `public/`; directory `700`, files `600`; names `<uuid>.<ext>` |
| Processing | Files are **never** opened, unzipped, rendered, thumbnailed or executed server-side. |
| Serving | Admin-only route; `application/octet-stream`, `Content-Disposition: attachment`, `nosniff`, `Content-Security-Policy: sandbox` on the response. SVGs are therefore never rendered in the site's origin. |
| Orphans | `pending` uploads > 24 h deleted hourly. |
| Disk | Upload endpoint returns `503 STORAGE_UNAVAILABLE` when disk usage > 95 %; alert at 70 % (see `DEPLOYMENT.md`). |
| Malware | Not scanned in v1 (files are only downloaded by staff). Admin UI shows a note: "Open files only from expected customers; scan ZIPs before extracting." ClamAV is in the v2 backlog. |

## 6. Bot and abuse protection

1. **Turnstile** (managed/invisible) on the quote form; token verified server-side with `TURNSTILE_SECRET_KEY` and `remoteip`; token single-use. Dev/CI use Cloudflare's always-pass test keys.
2. **Honeypot** field `website` (visually hidden, `tabindex=-1`, `autocomplete=off`); filled → silent fake success.
3. **Minimum fill time:** submissions < 3 s after form render (timestamp in a signed hidden field) treated as bot → silent fake success.
4. **Rate limits** (rate-limiter-flexible, memory, keyed by IP from `X-Forwarded-For` set by Nginx — only trust the first hop from `127.0.0.1`):

| Endpoint | Limit |
|---|---|
| `POST /api/uploads` | 10 / h, 2 concurrent |
| `POST /api/quotes` | 5 / h, 20 / day |
| Admin login | 5 / 15 min |
| `GET` pages | Nginx `limit_req` 20 r/s burst 40 per IP |

## 7. HTTP security headers

Set in `next.config.ts` `headers()` (and HSTS in Nginx):

| Header | Value |
|---|---|
| `Strict-Transport-Security` | `max-age=63072000; includeSubDomains; preload` (enable `preload` only after confirming all subdomains are HTTPS) |
| `Content-Security-Policy` | `default-src 'self'; script-src 'self' 'nonce-{n}' https://challenges.cloudflare.com https://www.googletagmanager.com; style-src 'self' 'unsafe-inline'; img-src 'self' data: https://res.cloudinary.com https://www.google-analytics.com https://www.googletagmanager.com; font-src 'self'; connect-src 'self' https://www.google-analytics.com https://*.google-analytics.com https://challenges.cloudflare.com; frame-src https://challenges.cloudflare.com https://www.google.com; form-action 'self'; frame-ancestors 'none'; base-uri 'self'; object-src 'none'; upgrade-insecure-requests` — nonce generated in `middleware.ts` |
| `X-Content-Type-Options` | `nosniff` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=(), payment=()` |
| `X-Frame-Options` | `DENY` |
| `Cross-Origin-Opener-Policy` | `same-origin` |

`frame-src https://www.google.com` is for the Google Maps embed on the Contact page (lazy, click-to-load).

## 8. Privacy — DPDP Act 2023 (India)

| Requirement | Implementation |
|---|---|
| Notice | Privacy Policy (`CONTENT.md` §7.1) states data collected, purposes, sharing, retention, rights and grievance contact. Linked next to the consent checkbox and in the footer. |
| Consent | Unticked checkbox: "I agree to VasuPrint contacting me about this enquiry and processing my details as described in the Privacy Policy." Stored with `noticeVersion` and timestamp. |
| Purpose limitation | Lead data used only to respond to the enquiry and fulfil orders. No marketing emails in v1. |
| Data minimisation | No date of birth, no ID documents, IP stored only as salted hash. |
| Retention | Owner decision: leads and artwork kept indefinitely for repeat orders. Policy states this and offers deletion on request. |
| Rights (access, correction, erasure, grievance) | Requests to the grievance contact email (placeholder in `business.ts`); admin can delete a lead and its files (FR-35). Respond within 30 days. |
| Processors | MongoDB Atlas (Mumbai), SMTP provider, Cloudinary (product images only, no customer data), Cloudflare Turnstile, Google Analytics. Listed in the policy. |
| Analytics | GA4 with IP anonymisation (default in GA4), no Google Signals, no ads features. India-only audience → no cookie consent banner in v1; revisit if EU/UK traffic targeted (v2). |
| Children | Site not directed at children; no data knowingly collected. |

## 9. Data protection at rest and in transit

- TLS 1.2+ only (Certbot Nginx defaults + `ssl_protocols TLSv1.2 TLSv1.3`).
- Atlas: TLS enforced, encryption at rest (default), dedicated DB user with `readWrite` on `vasuprint` only, network allowlist = VPS public IP only.
- SMTP over TLS (465 implicit or 587 STARTTLS with `requireTLS: true`).
- Backups encrypted with an rclone `crypt` remote; passphrase stored in the owner's password manager, not on GitHub.

## 10. VPS hardening (checklist; steps in `DEPLOYMENT.md`)

- [ ] Ubuntu 24.04 LTS, `unattended-upgrades` enabled for security updates.
- [ ] Non-root `deploy` user; root SSH login disabled; password auth disabled; SSH keys only.
- [ ] `ufw`: allow 22 (optionally restricted), 80, 443; deny everything else. Node listens on `127.0.0.1:3000` only.
- [ ] `fail2ban` for sshd and Nginx login-path abuse.
- [ ] Hostinger panel: 2FA enabled on the account; VPS snapshots weekly.
- [ ] Nginx: `server_tokens off`, default server returns 444 for unknown hosts.
- [ ] Only ports 80/443 publicly reachable — verified with `nmap` from outside.

## 11. Dependency and code hygiene

- `pnpm audit --prod` in CI; high/critical vulnerabilities fail the build (allowlist with expiry date in `audit-ci.jsonc` if a fix is unavailable).
- Dependabot weekly for npm and GitHub Actions; group minor/patch.
- Lockfile committed; CI uses `pnpm install --frozen-lockfile`.
- GitHub: branch protection on `main` (PR + passing CI required); secret scanning and push protection enabled.

## 12. Logging and incident response

- Never log: phone, email, names, file contents, request bodies, session tokens. Log lead **reference**, upload **id**, reason codes.
- Suspected compromise: (1) bump `SESSION_VERSION`, rotate `ADMIN_PASSWORD_HASH`, `SESSION_SECRET`, SMTP password, Atlas password, Cloudinary keys; (2) review `pm2 logs` and Nginx access logs; (3) restore from last clean snapshot if needed; (4) if lead data was exposed, notify affected buyers and the Data Protection Board as required by the DPDP Act.

## 13. Security test cases (must exist in the test suite)

1. Admin action without session → rejected (every exported action, enumerated automatically).
2. `/api/admin/*` without cookie → 401.
3. Upload `.png` containing PDF bytes → 415; `.exe` renamed to `.pdf` → 415; 100 MB + 1 byte → 413 and temp file removed.
4. Quote with another IP's `uploadId` → 400 `INVALID_UPLOADS`.
5. Quote with honeypot filled → 201 fake reference, no DB write.
6. Body containing `{"$gt": ""}` in a field → 400, no query executed.
7. CSV export escapes `=HYPERLINK(...)` as text.
8. Login: 6th attempt within 15 min → 429.
9. `Origin: https://evil.example` on `POST /api/quotes` → 403.
